# Agent Note: 三维宠物军团改版

Status: implemented

## Problem

2026-09-30 用户要求整体改版：宠物军团自动对战，十种宠物各三个形态（第三形态是修长帅气的人形态，带角、光环、披风、金饰），另有两形态的首领；技能特效随进化变化；5 对 5 到 10 对 10 的全自动战斗，玩家只点敌人集火，另可暂停、加速；美术全部用代码生成，要“精美的 3D”；局内成长（收服、进化），图鉴只做记录；原来的玩具小队版本不再保留。随后又要求：特效要是立体的，施展时要有特写，不能干巴巴不动；地图不要局限于五角星擂台，自由开放程度高一些，走位引入随机路径，双方步伐交错、切来切去。

这与两条已有的 Proposal 冲突：[视觉与声音方向](2026-09-24-visual-audio-direction.md) 的“采用有辨识度、轻松而不敷衍的二维表达”，以及 [新手指引改成游戏式教学](2026-09-27-game-style-tutorial.md) 的“按情形教”（课程按旧玩法的开局招式、主动招式编排）。

## Proposal

- 玩法：宠物军团自动对战。十种宠物分属水、火、木、岩、雷五系，各有幼年、进化形态、人形态三个形态，人形态获得大招；最后一场的首领烛龙有兽形与人形两个形态。可上场的宠物数随场次从 5 只增加到 10 只。理由：用户 2026-09-30 选定“整体改版”。
- 操作：战斗全自动，玩家只点敌人设集火，另可暂停和加速；战前可以拖动站位。理由：用户 2026-09-30 选定“全自动只点敌人集火”；[核心玩法](2026-09-24-core-gameplay.md) 要求自动战斗时站位与配置实际影响过程。
- 成长：一轮之内收服新宠物、让宠物进化；图鉴只记录见过的形态，不带跨局战力。理由：用户 2026-09-30 选定“一轮之内成长”；与核心玩法不做长期数值养成一致。
- 画面：三维卡通渲染，模型、动作、特效和场景全部由代码生成，不用图片或模型文件；人形态修长（约六头身），带角、光环、披风和金饰。取代“二维表达”一条；同一条里“避免工业控制台、赛博监控大屏、代码终端、整页企业仪表盘或通用后台模板”仍然有效，离线、不依赖在线素材的约束也不变。理由：用户 2026-09-30 要求“精美的 3D”，选定“代码生成”“修长帅气”。
- 特效与镜头：技能特效做成立体的，随进化升级；放技能时镜头推近特写，大招分两段（正面仰拍蓄力、侧面看出手），平时镜头缓慢漂移。特写有间隔，可在设置里关闭，特写时敌我与血量仍然看得见。理由：用户 2026-09-30 要求特效立体、施展时有特写；视觉 Note 要求明显的动效克制、敌我与关键状态始终看得清。
- 战场：开阔的野外战场取代五角星擂台，地形延伸到地平线；对战区域仍有边界（边缘结界），不做可探索的开放地图。走位带随机路径：侧移、后撤、绕行、交错换位。理由：用户 2026-09-30 要求地图更开放、步伐交错；核心玩法 Note 不做开放地图，这里开放的是视野，不是探索。
- 新手指引按情形分六课，各在对应情形第一次出现时教：第一次战前准备（看对手、认识军团、拖动站位、开战）、第一次开战（点敌人集火、暂停与加速）、第一次打出 2 级以上的回响（停在那一刻，圈出发生的位置）、我方第一次放大招、第一场结算、第一次挑奖励（收服、进化、确认）。每步一句话，合计 12 步。演示、照做推进、教学战、“？”重看的做法不变。取代“按情形教”一条。理由：旧课程教的开局招式、主动招式在新玩法里没有了；大招是新玩法里最需要讲的时刻。
- 旧版本存档：v0.4.0 及以前的存档读入时保留设置与通关记录，进行中的一轮无法沿用，丢弃并提示一次；新手指引重新教。理由：玩法整体改变，旧的一轮对应不到新规则，老玩家也要重新学。

## Decision

用户 2026-10-01 确认本 Proposal，取代 [视觉与声音方向](2026-09-24-visual-audio-direction.md) Proposal 中“二维表达”一条、[新手指引改成游戏式教学](2026-09-27-game-style-tutorial.md) Proposal 中“按情形教”一条；实现与 Proposal 一致，按下方 Plan 落实。规则细节见 [核心玩法](2026-09-24-core-gameplay.md) 的 Plan。

## Plan

- 渲染：three.js 随构建拷进 `dist/vendor`，页面用 import map 指向本地文件，离线可用。卡通材质加反向外壳描边，后期有泛光与调色；四档画质（阴影、泛光、粒子量、分辨率），自动档按实际帧率升降、最高到中档，设置里可以固定；没有显卡时用软件渲染兜底。帧率上限和闪光的克制见 [视觉与声音方向](2026-09-24-visual-audio-direction.md)。
- 造型：建模工具把部件拼成带骨骼的网格，双足、四足、飞行三套程序动画；表情、头发、服装都由代码生成。规则层 100 个单位对应 1 米，模型统一放大 1.28 倍以便看清。
- 战场：六种野外主题（草原、火山、潟湖、雷暴高地、峡谷、云上遗迹），按对手的主题属性选，首领在云上遗迹；高度图地形加程序纹理，草丛随风摆动。对战区 18×11 米，靠镜头一侧的地形压低，不挡视线。
- 走位：规则层给出侧移、后撤、绕行、交错换位等步伐，随机但可复现（同一场种子相同）；动画按移动方向与朝向的夹角换成侧步、后撤步。
- 镜头：自动框住交战区域（人多时去掉两头的离群者），俯角 38°，缓慢漂移。特写从几个候选机位里挑视线挡得最少的，仍然挡在镜头前的单位在特写期间暂时隐去。间隔：技能特写约 3 秒一次，我方大招 6 秒、对手大招 11 秒，没轮上的只给短暂慢动作。特写时血条与数字变淡，不消失。
- 特效：立体刀光、冲击波光壳、漩涡、翻滚溶解的火球、水花、雷球、结界闪光，以及按物理飞散的碎块（岩石、晶体、叶片、冰、余烬、花瓣）。粒子、特效、碎块各有上限，战前预热会用到的材质，避免开打时卡顿。
- 声音：Web Audio 程序合成，按新事件重写（五系命中、克制提示、回响音阶、大招和弦、烛龙变身等），同时发声数量有上限。

## Verification

- 端到端测试 16 项，本地 Linux 开发版与 CI（Linux 开发版、打包好的 macOS 和 Windows 客户端）都通过：选伙伴开局与存档写入；打赢一场后收服与进化、进入下一场；战斗中关闭重开回到战前；输了原样再来或回去调整；设置重启后保留；清除存档留下备份；空格暂停、点敌人集火、失焦自动暂停；拖动站位写入存档；最后一场后的整轮结算。指引：新安装依次教、照做推进、跳过、教学战（含大招课）、“？”重看、v0.4.0 存档升级。特效：十只人形态对首领的整场里技能特写与大招镜头都出现、各类特效数量不超上限；关掉特写、打开“减少闪烁”后首领战照常打完。
- 单元测试 63 项覆盖规则层：相克与伤害、各技能与大招、回响与上限、步法、首领变身、集火、加时与时限、同种子复现、一轮流程与奖励、存档往返与旧版迁移。自动对战报告（不集火、不调站位）显示标准难度每场 40–80 秒，“先进化”“伙伴带队”两种思路每一场第一次尝试的胜率都在 63% 以上。
- 截图检查了标题、选伙伴、战前（含指引）、战斗、技能特写、大招镜头、首领战、结算、奖励、进化演出、图鉴与设置。大招镜头初版会被别的单位挡住（镜头钻进烛龙身体里），加入候选机位与遮挡隐去后解决。
- 帧率只在 Linux 无显卡（软件渲染）环境测过：画质自动降到最低档，十只人形态对首领时镜头推近大体型单位会明显掉帧；有显卡的 Mac、Windows 真机上的观感与帧率未测。声音未试听（开发环境没有音频输出）。
- 待确认：真人玩一轮的时长（按自动对战估计约 15–20 分钟）、难度与观感，需要用户试玩判断。
