# Agent Note: 暂停、存档与恢复

Status: implemented

## Problem

这是随时打开、随时可能被打断的本地游戏。需要确定保存哪些内容、何时保存、存到哪里、关闭后如何继续，以及怎样安全重置。

## Proposal

- 提供明确的暂停、继续和新开一轮入口，不用创建账号来解决保存。理由：Brief §5。
- 至少保存当前进程、已做出的局内选择、战前检查点和基础设置；可以只恢复到战前状态，但不能丢掉重要决定，并要让玩家清楚从哪里继续。理由：Brief §5。
- 可能覆盖当前进度的操作要有清楚提示。理由：Brief §5。
- 窗口失焦或系统打断时，不继续制造难以察觉的损失。理由：Brief §6。
- 存档和设置留在本地，交付时说明位置和安全重置方式；不读取其他个人文件，不收集遥测。理由：Brief §9。

## Decision

与 Proposal 一致，按下方 Plan 落实。

## Plan

- 检查点：战前准备的改动（短暂合并后写入）、开战（记下“战斗中”）、待选奖励和整轮结束时写入。战斗进行中不保存中间状态，中途离开后回到该场战前准备，标题页说明从哪里继续。
- 存储：客户端主进程把 JSON 原子写入用户数据目录（macOS `~/Library/Application Support/EchoArena/`，Windows `%APPDATA%\EchoArena\`），并保留上一版备份；关闭窗口前同步写入。在普通浏览器里开发时改用 localStorage。
- 窗口失焦或最小化时自动暂停（可在设置中关闭），最小化时同时挂起声音。
- 新开一轮会覆盖当前进度时二次确认；设置中提供“清除全部存档”，确认后原存档改名为备份保留一次。

## Acceptance criteria

- 关闭客户端后重新打开，能回到正确的场次与配置，并有说明。
- 设置修改在重启后保留；重置操作有确认，重置后的状态干净。

## Verification

- 客户端端到端测试（Linux 开发版，以及 CI 中打包好的 macOS 与 Windows 客户端）覆盖：战斗中关闭再打开回到同一场战前准备且招式不丢、战前调整写入存档、设置重启后保留、清除存档后回到初次状态并留下备份、失焦自动暂停。
- 单元测试覆盖存档往返、损坏或陌生存档的处理和非法配置清理。
