# Agent Note: 暂停、存档与恢复

Status: implemented

## Problem

这是随时打开、随时可能被打断的本地游戏。需要确定保存哪些内容、何时保存、存到哪里、关闭后如何继续，以及怎样安全重置。

## Proposal

- 提供明确的暂停、继续和新开一轮入口，不用创建账号来解决保存。理由：Brief §5。
- 至少保存当前进程、已做出的局内选择、战前检查点和基础设置；可以只恢复到战前状态，但不能丢掉重要决定，并要让玩家清楚从哪里继续。理由：Brief §5。
- 可能覆盖当前进度的操作要有清楚提示。理由：Brief §5。
- 窗口失焦或系统打断时，不继续制造难以察觉的损失。理由：Brief §6。
- 存档和设置留在本地，交付时说明位置和安全重置方式；不读取其他个人文件，不收集遥测。理由：Brief §9。

## Decision

与 Proposal 一致，按下方 Plan 落实。

## Plan

- 检查点：战前准备的改动（短暂合并后写入）、开战（记下“战斗中”）、待选奖励和整轮结束时写入。战斗进行中不保存中间状态，中途离开后回到该场战前准备，标题页“继续征程”下方说明从哪里继续（战斗中离开、奖励还没领、这一轮已打完）。
- 存储：客户端主进程把 JSON 原子写入用户数据目录（macOS `~/Library/Application Support/EchoArena/`，Windows `%APPDATA%\EchoArena\`），并保留上一版备份。写入与清除按调用顺序排队，换上新存档一步同步完成，已经有更新的内容落盘时丢弃旧的写入；关闭窗口前同步写入最新存档（还有写入没确认写完时也写）。在普通浏览器里开发时改用 localStorage。
- 窗口失焦或最小化时自动暂停（可在设置中关闭），画面中间提示“已自动暂停”，同时挂起声音；空格暂停时提示“已暂停”。
- 新开一轮会覆盖当前进度时二次确认；设置中提供“清除全部存档”，确认后原存档改名为备份保留一次。
- 从 v0.4.0 及以前升级（存档格式升到版本 4）：旧玩法的那一轮无法沿用，读入时丢弃并提示一次；设置与通关记录保留，图鉴从空开始（见 [三维宠物军团改版](2026-09-30-3d-pet-legion.md)）。

## Acceptance criteria

- 关闭客户端后重新打开，能回到正确的场次与配置，并有说明。
- 设置修改在重启后保留；重置操作有确认，重置后的状态干净。

## Verification

- 客户端端到端测试（Linux 开发版，以及 CI 中打包好的 macOS 与 Windows 客户端）覆盖：战斗中关闭再打开回到同一场战前准备且军团与站位不丢、战前拖动站位写入存档、设置重启后保留、清除存档后回到初次状态并留下备份、空格暂停与失焦自动暂停、旧玩法存档升级后丢弃那一轮并提示。
- 单元测试覆盖存档往返、损坏或陌生存档的处理和非法配置清理；另有存档文件的写入顺序（放慢写入模拟慢磁盘）：两次写入重叠、关闭前同步写入之后还有旧写入没落盘、清除存档排在写入之后，磁盘上留下的都是最新的一次。
- 2026-09-27 CI 的 macOS 打包任务暴露过写入顺序问题：拖动站位后紧接着开战、随即关闭，存档里留下的是拖动前的站位。原因是异步写入不排队、共用临时文件，较早的写入可能最后落盘；关闭时还有写入没写完也不会补写。按上面的存储方式修正。
