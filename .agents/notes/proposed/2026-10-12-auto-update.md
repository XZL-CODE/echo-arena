# Agent Note: 应用内自动更新

Status: proposed

## Problem

到 v0.5.1 为止，玩家只能自己去 Releases 页面下载新版重装，也不知道出了新版本。用户 2026-10-12 要求为游戏添加自动更新推送。需要定下更新源、防篡改办法、检查与提示方式，以及联网的边界：[跨平台本地运行技术栈](../implemented/2026-09-24-cross-platform-local-stack.md)约定首次安装后离线运行。

## Proposal

- 更新源用 GitHub Release，不设服务器：每次发版附一份 `latest.json`（版本、更新说明、各平台安装包的地址与签名），客户端读固定地址 `releases/latest/download/latest.json`，只接受比自己高的版本。理由：仓库与 Release 已公开，这个地址总是指向最新的正式版本。
- 更新包用作者已有的 minisign（Ed25519）密钥签名，公钥写进客户端，签名对不上就不安装。私钥与密码只放在仓库 Secret（`TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`）和作者的密码管理器里，不进仓库和对话，也不另生成密钥。理由：没有付费的苹果、微软代码签名也能防篡改；作者各应用共用这一套。
- macOS 与 Windows 安装版点“立即更新”后自动下载、核对签名、安装并重新打开；Windows 免安装版、从源码运行的版本，以及不在可写位置的 macOS 应用（直接从 dmg 里打开等），只提示新版本并打开下载页。理由：用户 2026-10-12 选定两个平台一键更新；后几种没有可替换的安装位置。
- 只在检查和下载更新时访问 GitHub，此外运行时不发起外部网络请求；没网照常离线游玩。设置里可关掉自动检查，关掉后只在手动点“检查更新”时联网。理由：“首次安装后离线运行、不需要持续联网”仍然成立，联网范围对玩家说清楚。
- 自动检查默认开：启动几秒后在后台查，每天最多一次；发现的新版本没装之前每次启动都查。失败不弹提示，原因显示在设置里。理由：默认关等于没人收到更新；用户 2026-10-12 选定。
- 发现新版本时在标题页出现“新版本 vX”按钮，点开才显示更新说明与“立即更新 / 稍后 / 在浏览器中查看”；不弹窗打断，战斗中不出现。理由：用户 2026-10-12 选定。

## Consequences

- v0.5.1 及以前的版本没有检查功能，玩家要手动下载一次带更新功能的版本。
- 密钥与作者其他应用共用：私钥丢失后所有应用都推不了更新，泄露时要一起更换，换密钥后老用户要手动重装一次。
- 发版前仓库里要先有上面两个 Secret；缺了发布任务直接失败，不会发出没有签名的版本。

## Plan

- 主进程 `electron/updater.cjs`：用 Chromium 的网络栈（`net.fetch`，跟随系统代理）读清单，20 秒超时；下载时一分钟收不到数据才放弃，整体不限时。边下载边算 BLAKE2b-512（Electron 的 BoringSSL 没有这个算法，用纯 JS 实现，约 40 MB/s），下完核对 Ed25519 签名与全局签名，并要求签名可信注释里的版本号与清单一致（防止清单被改成用旧版本的安装包冒充新版本）；key id 不对、内容被改、版本对不上都不装，下载的文件当场删掉。
- 安装：macOS 挂载 dmg、拷出新的 .app，游戏退出后由辅助脚本把旧 .app 挪开、换上新的（失败就放回旧的），再打开；应用自己下载的文件不带隔离标记，换上后不会被 Gatekeeper 拦。Windows 静默运行 NSIS 安装包（`--updated /S --force-run`），沿用原来的安装位置与安装方式，装完由安装包重新打开游戏；退出前弹窗说明“装好后会自动重新打开”。
- 页面 `src/ui/updates.tsx`：启动 5 秒后按设置决定要不要检查；自动检查开关和上次检查记录存在存档的设置里，清除存档时一起重置。弹窗的更新说明取 Release 正文，去掉“更新内容”标题与“安装说明”一节。
- 发版（`.github/workflows/build.yml` 的发布任务与 `scripts/release-update.mjs`）：各平台打包与测试都通过后，用 Tauri 命令行工具（固定版本）给 dmg 与 Windows 安装版签名并写进版本号，再用客户端内置的公钥和客户端读版本号的同一个函数核对一遍，生成 `latest.json` 与 Release 正文。更新内容取合并进来的 PR 正文里“## 更新内容”一节，没有就用自动生成的 PR 列表；后面是安装说明。Release 先建成草稿、附件全部传完再公开；要发布的版本必须与 `package.json` 一致，否则装上的程序还是旧版本号，会一直提示更新。分支与 PR 的流水线先用私钥签一个小文件、用公钥核对（连同读出签名里的版本号），Secret 不对或签名器的格式变了，合并前就会失败。
- 测试：单元测试核对 BLAKE2b 与 OpenSSL 结果一致、签名核对、版本比较、清单与正文的格式；端到端测试用本机的假更新源和测试密钥，走完发现新版本、看说明、下载并核对（测试模式不安装）、签名不对或版本对不上时拒装、一天内不重复检查。CI 的打包任务里再用刚打出的安装包冒充新版本，真正替换安装，核对游戏重新打开。
